# System design curriculum

The curriculum progresses from tracing a request to planning a multi-region migration. Each module introduces a concept, asks the learner to use it in a design, and defines the behavior a reviewer should see.

| Module | Topics and prerequisites | Demonstration and primary reading |
| --- | --- | --- |
| 1. System design fundamentals | Requirements, throughput, latency percentiles, availability, capacity, CAP introduction. Basic programming. | Estimate a peak read workload, translate a latency objective into a measurement, and draw a single-service baseline. [Google SRE service-level objectives](https://sre.google/sre-book/service-level-objectives/) |
| 2. Networking and APIs | DNS, TCP, TLS, HTTP, REST, gRPC, WebSockets, API gateways. Module 1. | Choose a protocol for an upload and a live status feed. Define the timeout and retry contract. [IETF RFC 9110, June 2022](https://www.rfc-editor.org/rfc/rfc9110.html), [gRPC core concepts](https://grpc.io/docs/what-is-grpc/core-concepts/) |
| 3. Database engineering | SQL and NoSQL, data modeling, indexes, replication, partitioning, sharding, isolation. Modules 1–2. | Derive an index from an access pattern and prevent a reservation race with a database constraint or locking strategy. [PostgreSQL transaction isolation](https://www.postgresql.org/docs/current/transaction-iso.html), [Amazon Dynamo, October 2007](https://www.allthingsdistributed.com/2007/10/amazons_dynamo.html) |
| 4. Caching systems | Cache-aside, write-through, Redis, CDN, TTLs, invalidation, LRU/LFU, stampedes. Modules 2–3. | Calculate cache-miss load and protect the backing store after expiry or cache loss. [Redis key eviction](https://redis.io/docs/latest/develop/reference/eviction/), [Meta memcache, April 2013](https://engineering.fb.com/2013/04/15/core-infra/scaling-memcache-at-facebook/) |
| 5. Load balancing and rate limiting | Reverse proxies, L4/L7, health checks, routing, token buckets, backpressure. Modules 1–2. | Set a request budget and explain the guarantee when traffic is spread across several nodes. [Google SRE load balancing](https://sre.google/sre-book/load-balancing-datacenter/), [Google SRE handling overload](https://sre.google/sre-book/handling-overload/) |
| 6. Distributed systems | Consistency models, CAP during partitions, consensus, replication, leader election, transactions, fencing. Module 3. | Explain what two clients can see during failover, then specify a recovery or reconciliation rule. [Raft, USENIX ATC 2014](https://www.usenix.org/conference/atc14/technical-sessions/presentation/ongaro), [Amazon Dynamo, October 2007](https://www.allthingsdistributed.com/2007/10/amazons_dynamo.html) |
| 7. Messaging and event streaming | Queues and logs, Kafka, RabbitMQ, SQS, Pub/Sub, partition ordering, delivery, outbox, replay and DLQs. Modules 3 and 6. | Choose partition keys and demonstrate recovery after a consumer crashes between a side effect and an acknowledgment. [Apache Kafka design](https://kafka.apache.org/design/), [Amazon SQS at-least-once delivery](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/standard-queues-at-least-once-delivery.html) |
| 8. Microservices and low-level design | Service boundaries, discovery, saga, CQRS, circuit breakers, interfaces, state machines, concurrency, multithreading, bounded executors. Modules 2–3 and 7. | Draw a service API and component state machine, then explain how concurrent state transitions and worker shutdown preserve invariants. [Java concurrency package](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/package-summary.html), [AWS saga patterns](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/saga-patterns.html) |
| 9. Storage and search | Blob and object storage, S3, indexing, Elasticsearch, Bloom filters, geospatial access. Modules 3–4 and 7. | Separate blob bytes from metadata and design search freshness, indexing backlog, and deletion handling. [Amazon S3 consistency](https://aws.amazon.com/s3/consistency/), [Elastic inverted index](https://www.elastic.co/docs/reference/glossary#glossary-inverted-index), [Uber H3, June 2018](https://www.uber.com/us/en/blog/h3/) |
| 10. Cloud and DevOps | AWS, GCP and Azure primitives, Docker, Kubernetes, CI/CD, rollout, alerting, and tracing. Modules 5 and 8. | Deploy a stateless API with health checks, a versioned database migration, and a rollback plan. [Kubernetes overview](https://kubernetes.io/docs/concepts/overview/), [Azure Well-Architected Framework](https://learn.microsoft.com/en-us/azure/well-architected/what-is-well-architected-framework) |
| 11. Security and reliability | OAuth, JWT, authorization, encryption, error budgets, retries, failover, and disaster recovery. Modules 6–8 and 10. | Draw trust boundaries, defend a least-privilege grant, and state how a restore verifies RTO and RPO. [IETF OAuth 2.0 Security Best Current Practice, January 2025](https://www.rfc-editor.org/rfc/rfc9700.html), [AWS Builders' Library on retries, December 2019](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/) |
| 12. Machine learning and AI systems | Feature and recommendation pipelines, RAG, vector retrieval, inference, agent orchestration, quality, cost and failure modes. Modules 7, 9, and 11. | Design an offline and online evaluation plan for a retrieval pipeline and add a fallback when the model lacks evidence. [RAG paper, 2020](https://arxiv.org/abs/2005.11401), [pgvector documentation](https://github.com/pgvector/pgvector) |
| 13. Interview case studies | Requirements discovery, HLD and LLD reasoning, capacity assumptions, trade-offs, and communication. Prerequisites depend on the chosen case. | Rework a design after an added constraint and compare rubric outcomes. Practice archetypes include chat, rides, video upload and streaming, feeds, checkout, and link redirection. |

## Project playlists

Each list is in recommended practice order. Problems use original scenarios. Named services serve as public engineering reading where relevant.

| Playlist | Problems in order | End-of-path skill |
| --- | --- | --- |
| Beginner | Short links for conference materials, per-tenant API rate limiter, expiring paste service, resumable file upload, multi-level parking garage | Ship a small service with a measurable capacity estimate and an enforceable invariant. |
| Intermediate | Neighborhood group chat, meeting notification service, creator activity feed, lecture video uploads, photo album sharing | Handle asynchronous work, queues, and uneven read and write traffic. |
| Advanced | Courier dispatch, local map search, payment ledger, [workshop seat reservations](../content/projects/workshop-seat-reservations.md), marketplace checkout | Reason about concurrency, money or inventory consistency, failure isolation, and migration. |
| Modern AI | Cited support assistant, document ingestion and RAG service, multi-tenant vector search, marketplace recommendations, asynchronous agent jobs | Define retrieval and serving quality, permission boundaries, latency and spend budgets, and degradation. |

## Progression from beginner to staff

- **Beginner.** Work through modules 1–5 and the beginner playlist. A passing checkpoint includes a request path, a correctly dimensioned estimate, and a stated API contract.
- **Mid-level.** Add modules 6–9 and the intermediate playlist. Pass by identifying a workload bottleneck, carrying one consistency requirement through the design, and explaining how to recover from a duplicate or failed operation.
- **Senior.** Use modules 6–13 and advanced cases. Pass by comparing two viable solutions under the same constraints, explaining a partial failure end to end, and justifying observable thresholds and capacity assumptions.
- **Staff.** Revisit senior designs under changed organizational or regional constraints. Pass by giving a staged migration with ownership, compatibility, rollback, cost range, and measurable stop conditions.

## First content release

The pilot starts with six lessons on requirements and capacity, API idempotency, database isolation, cache failure, asynchronous delivery, and reliability objectives. It includes workshop seat reservations and an expiring link or paste exercise. The paid MVP target is 16 reviewed lessons, at least 10 available free, eight guided problems, and three end-to-end projects. Add coverage only as fast as reviewers can verify the worked examples and evaluate the rubrics.

Every lesson has learning objectives, first-principles explanation, an engineering example, a diagram, benefits and drawbacks, trade-offs, interview questions, a practical exercise, a quiz with answers, and further reading. Use the [idempotent retries lesson](../content/lessons/idempotent-retries.md) as a reference format.

Every project includes requirements, assumptions and capacity, APIs, data model, high-level and detailed architecture, scaling and failure recovery, security, cost drivers, decision trade-offs, a build exercise, and a scoring rubric. Follow the [workshop seat reservation project](../content/projects/workshop-seat-reservations.md).
